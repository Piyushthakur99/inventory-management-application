# Deployment (Free/Low-cost Options)

This project is **Spring Boot + MongoDB + static HTML/JS**.

## Key points before you deploy

- You need a **cloud MongoDB** (free tier works): MongoDB Atlas M0.
- If you enable OpenAI features, OpenAI usage is **not free**. By default, OpenAI is disabled.
- For a public deployment, set a strong `JWT_SECRET` and usually disable demo seeding.

## Option A (recommended): One public URL (backend serves the frontend)

This repo is set up so the backend jar can serve the `frontend/` files from the same origin.

### 1) Create a free MongoDB Atlas database

1. Create an Atlas account and a free **M0** cluster.
2. Create a database user + password.
3. In **Network Access**, allow your hosting provider to connect.
   - Many free hosts require `0.0.0.0/0` (open) because their outbound IPs vary.
   - If you do this, use a strong DB password.
4. Copy the connection string, it looks like:

`mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/inventory_db?retryWrites=true&w=majority`

### 2) Deploy the backend on a free host

Pick a host that can run Docker or a Java web service. Free tiers change often, but these commonly work:

- **Render** (often has a free web-service tier with sleep)
- **Koyeb** (has a free tier in some regions)
- **Fly.io** (free allowances sometimes, may require a card)
- **Google Cloud Run** (very generous free quota, requires billing account)

If your host supports **Docker**, use the Dockerfile at `backend/Dockerfile`.

#### Render (recommended)

This repo includes a Render Blueprint at `render.yaml` so you can deploy without manually entering Docker paths.

1. Push this repo to GitHub.
2. In Render Dashboard: **New +** → **Blueprint**
3. Select your GitHub repo (the one containing `render.yaml`).
4. When prompted for environment variables, set:
  - `MONGODB_URI` = your MongoDB Atlas connection string
  - `JWT_SECRET` is auto-generated by Render (no action needed)
5. Click **Apply**.

After deploy, your app URL will be the single public URL for both frontend + backend.

Note: Render uses `/actuator/health/liveness` as the service health check so deploys don't fail if MongoDB is briefly unavailable during startup.

#### Environment variables to set on the host

- `MONGODB_URI` = your Atlas connection string
- `JWT_SECRET` = a long random secret
- `APP_DEMO_SEED_USERS` = `false` (recommended for public deployments)
- `APP_EMAIL_ENABLED` = `false` (unless you configure Gmail SMTP)

The app binds to the host port automatically via `PORT`.

### 3) Verify

- Open the public URL → you should see the login page.
- Health check: `/actuator/health`

## Option B: Two URLs (static frontend + API backend)

If you prefer hosting static pages separately:

- Frontend: GitHub Pages / Cloudflare Pages / Netlify
- Backend: Render / Koyeb / Fly.io / Cloud Run

In that case, the frontend must call the backend URL.

### Configure frontend API base URL

The frontend uses this logic:

- If `window.__API_BASE_URL__` is set, it will use that.
- Otherwise on localhost it defaults to `http://localhost:8080`.
- Otherwise it assumes same-origin.

So for separate hosting, set in each HTML (or in your layout/template if you have one):

```html
<script>
  window.__API_BASE_URL__ = 'https://YOUR-BACKEND-URL';
</script>
```

Add it **before** `js/auth.js` / `js/api.js`.
